## 已核实的具体缺陷（人工定位到机制）

自动归因只把差异分类；下面这些是已经查到底、能直接开工的问题。

### VF-01（高）Financial 表的溯源字段全表为空

证据：Financial 表共 2,134,334 行：rawXbrlTag 非空 0 行；mappingRule 非空 2,722 行（0.13%），其中 125 行是 2026-10-14 新增的派生毛利（mappingRule='derived:Revenue - CostOfRevenue'），其余是历史遗留。confidence 除派生行外恒为 1。模型里备了 rawXbrlTag / mappingRule / confidence 三件套用来回答「这个数是从哪来的」，实际上等于全部空置。

复现：
```bash
npx tsx -e "import {PrismaClient} from '@prisma/client';const db=new PrismaClient();(async()=>{console.log(await db.financial.count(), await db.financial.count({where:{rawXbrlTag:{not:null}}}));await db.\$disconnect()})()"
```

建议动作：这是「数据真实可靠」的地基：没有 tag 就无法回答「这个数是从哪来的」。先修注入管线把 tag 写进去，再加一条「FY 金额行必须有 tag」的完整性校验。

## 模型层矛盾（脚本自动检出）

字典里同一个晨星条目被我方多个科目认领——这是模型定义冲突，与数据质量无关，但会让对应科目永远比不平。

| 晨星条目 | 认领我方科目 | 状态 | 结论 |
| --- | --- | --- | --- |
| `IFIS001700` | SellingExpense / AdministrativeExpense / SGAExpense | 已由契约裁决 | SellingExpense / AdministrativeExpense / SGAExpense 三方重复认领。 |
| `IFBS000350` | CashAndCashEquivalents / ShortTermInvestments | 已由契约裁决 | CashAndCashEquivalents 与 ShortTermInvestments 重复认领，见上方 sum_of/absorbed。 |
| `IFCF001330` | CapEx / PurchaseSaleOfPPE | **待裁决** | CapEx 与 PurchaseSaleOfPPE 重复认领。已核实：对 MCD / PEP / 1810.HK 这些公司，该条目返回的晨星值比我方购建支出小两到三个数量级（MCD FY2021 我方 20.4 亿 vs 晨星 1.06 亿），量级上不可能是 CapEx —— 需要打开晨星快照原文确认这个 id 到底是什么口径。 |

另有 7 项字典科目没有任何 XBRL tag 且无晨星条目，属纯派生/纯本地科目：NonOperatingExpense、ConstructionInProgress、CashReceivedFromSales、CashBeginningOfPeriod、AssetsUnderManagement、NetClientFlows、InvestmentManagementFeeIncome。

## 管线层缺陷

- **年度汇率缺位**：库内 `FxRate` 只有 10 行，全部是 2026-10-12 的单日 spot 快照，没有历史年度汇率；而评测脚本用硬编码的 `YEAR_END_CNY_PER_USD` 兜底，该表又缺 FY2025。两边都撑不起历史年度换算，FY2025 的跨币种比对因此整体失效。
- 评测脚本用「第一条非 shares 的 unit」判断公司币种，遇到混入 ratio 行的公司会静默取错币种。
